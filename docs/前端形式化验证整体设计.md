# 1 概述

编译器前端负责将EVM Bytecode转换为EVM IR。前端验证采用Isabelle进行完全白盒验证，深入编译器实现细节，证明转换的正确性。

## 1.1 验证目标

前端验证的主要目标是：

1.  **语义保持性证明**：证明EVM Bytecode到EVM IR的转换保持语义不变
    
2.  **转换规则正确性**：证明前端编译器的转换规则是正确的
    
3.  **完整性验证**：验证所有EVM Bytecode指令都能正确转换为EVM IR
    

**形式化目标：**

对于任意EVM Bytecode程序 `P_bytecode` 和其对应的EVM IR程序 `P_ir`，证明：

```haskell
∀ inputs. semantics_bytecode(P_bytecode, inputs) = semantics_ir(P_ir, inputs)


```

即对于所有可能的输入状态，EVM Bytecode和EVM IR产生相同的执行结果。

## 1.2 验证策略

采用**分步骤证明**策略，将EVM Bytecode到EVM IR的复杂转换过程拆分为多个可独立证明的小步骤，每个步骤对应编译器的一个优化或转换阶段。

**核心思路**：

*   将完整编译过程分解为多个步骤（Step 1, Step 2, Step 3, Step 4...）
    
*   每个步骤独立证明编译前后语义等价
    
*   通过组合各步骤的证明，得出整体编译过程保持语义等价的结论
    

**证明流程**：

每个步骤的证明都包含：语义建模 → 转换规则建模 → 正确性证明

**关键要求**：

*   每个步骤中的所有转换规则都需要单独建模和单独证明
    
*   每个转换规则都需要证明执行结果、内存、Gas消耗、报错等的一致性
    

具体步骤和详细证明思路见第4章"正确性证明"。

# 2 形式化建模

## 2.1 EVM Bytecode语义建模

**理论文件：** `EVM_Bytecode_Semantics.thy`

**核心内容：**

*   定义EVM指令类型（`inst`）
    
*   定义执行状态（`variable_ctx`）
    
*   定义指令语义函数（`instruction_sem`）
    
*   定义程序执行语义（`program_sem`）
    

**关键定义：**

```isabelle
(* 指令语义：单步执行 *)
instruction_sem :: "variable_ctx ⇒ inst ⇒ instruction_result"

(* 程序语义：多步执行 *)
program_sem :: "nat ⇒ instruction_result ⇒ instruction_result"


```

## 2.2 EVM IR语义建模

**理论文件：** `EVM_IR_Semantics.thy`, `EVM_IR_Sem_Step1.thy`

**核心内容：**

*   定义IR操作符类型（`evm_operator`）
    
*   定义IR执行状态（`simple_ir_state`）
    
*   定义IR操作语义（`instruction_sem_step1`）
    
*   定义IR程序执行语义（`program_ir_sem_step1`）
    

**关键定义：**

```isabelle
(* IR操作符语义：支持优化的JUMP/JUMPI *)
instruction_sem_step1 :: "variable_ctx ⇒ simple_ir_state ⇒ evm_operator ⇒ instruction_result"

(* IR程序语义 *)
program_ir_sem_step1 :: "simple_ir_state ⇒ nat ⇒ instruction_result ⇒ instruction_result"


```

**Step1特殊处理：**

*   优化的JUMP指令：`ir_jump_imm` - 直接使用立即数跳转
    
*   优化的JUMPI指令：`ir_jumpi_imm` - 从栈pop条件，使用立即数跳转
    
*   Gas计算：`ir_jump_imm_gas`, `ir_jumpi_imm_gas` - 等于原PUSH+JUMP/JUMPI的总和
    

# 3 编译规则建模

## 3.1 Step1：指令合并规则

**理论文件：** `EVM_IR_Trans_Step1.thy`

**核心转换规则：**

1.  **PUSH+JUMP模式合并**
    
    *   输入：`PUSH_N bytes; JUMP`
        
    *   输出：优化的JUMP操作符（`operator_is_static = True`, `operator_immediate = Some addr`）
        
2.  **PUSH+JUMPI模式合并**
    
    *   输入：`PUSH_N bytes; JUMPI`
        
    *   输出：优化的JUMPI操作符（`operator_is_static = True`, `operator_immediate = Some addr`）
        
3.  **普通指令直接转换**
    
    *   其他指令直接转换为对应的IR操作符（`operator_is_static = False`）
        

**编译函数：**

```isabelle
compile_step1 :: "byte list ⇒ evm_operator list"


```

**编译关系：**

```isabelle
compile_rel_step1 :: "inst list ⇒ evm_operator list ⇒ bool"


```

定义源指令列表与目标操作符列表的结构对应关系。

# 4 正确性证明

## 4.1 证明思路概述

正确性证明采用**分步骤证明**策略，核心思路是：

**证明目标**：证明EVM Bytecode到EVM IR的编译过程保持语义等价，即对于任意输入，编译前后的程序产生相同的执行结果。

**证明方法**：将完整的编译过程拆分为多个可独立证明的小步骤（Step 1, Step 2, Step 3, Step 4...），每个步骤对应编译器的一个优化或转换阶段：

1.  **Step 1：结构变化** - 证明结构转换前后语义等价
    
2.  **Step 2：指令合并** - 证明指令合并前后语义等价
    
3.  **Step 3：指令分块** - 证明JUMPDEST+TAG分块前后语义等价
    
4.  **Step 4：指令新增** - 证明BLOCKEND新增前后语义等价
    

**证明原理**：如果每个小步骤都能证明编译前后语义等价，那么通过组合这些小步的证明，可以得出整体编译过程保持语义等价的结论。

每个步骤的证明都包含：语义建模 → 转换规则建模 → 正确性证明

## 4.2 证明步骤

每个步骤都需要证明转换前后在以下方面的一致性：

*   **执行结果一致性** - 返回值、输出数据等
    
*   **内存状态一致性** - 内存内容、内存大小等
    
*   **Gas消耗一致性** - 静态Gas和动态Gas的计算
    
*   **错误处理一致性** - 报错类型、错误码等
    
*   **其他状态一致性** - 存储状态、栈状态等（如适用）
    

**Step 1：结构变化正确性证明**

*   证明结构转换前后语义等价
    
*   保证执行结果、内存、Gas消耗、报错等的一致性
    

**Step 2：指令合并正确性证明**

*   证明指令合并前后语义等价（如PUSH+JUMP/JUMPI合并）
    
*   保证执行结果、内存、Gas消耗、报错等的一致性
    

**Step 3：指令分块正确性证明**

*   证明JUMPDEST+TAG分块前后语义等价
    
*   保证执行结果、内存、Gas消耗、报错等的一致性
    

**Step 4：指令新增正确性证明**

*   证明BLOCKEND新增前后语义等价
    
*   保证执行结果、内存、Gas消耗、报错等的一致性
    

**具体证明设计将在详细设计文档中给出。**
