# 1 引言

## 1.1 编写目标

本文档旨在详细描述EVM AOT形式化（黑盒）验证系统的设计方案。EVM AOT形式化（黑盒）是指将EVM AOT编译器作为黑盒对其进行形式化验证，其基本思路为Translate Validation，即对于特定的合约字节码，证明AOT编译器的编译结果的执行和直接解释合约字节码等价。此种证明方式可以证明EVM AOT编译器对于特定合约在所有输入以及状态下与EVM解释执行一致（无BUG）。

# 2 功能背景

## 2.1 现存问题

EVM AOT编译器将EVM字节码编译为x86-64机器码，以提高执行效率。然而，编译器的正确性需要得到保证，即编译后的x86代码必须与原始EVM字节码在所有输入下产生相同的执行结果。传统的测试方法只能覆盖有限的测试用例，无法保证在所有可能输入下的正确性。

## 2.2 解决方案

采用形式化验证方法，采用白盒与黑盒相结合的方式。**白盒**验证控制流，**黑盒**将EVM字节码（或EVM IR）和对应的x86-64 AOT编译结果都建模为逻辑公式，使用Z3求解器证明它们在所有输入下产生相同的输出状态。核心思想是直接对整个程序进行语义等价性验证，即验证EVM字节码和对应的x86-64 AOT编译结果在整个程序级别上的语义等价性。

**黑盒验证目标：**

证明对于整个程序P：

```haskell
∀ inputs. EVM_Program_P(inputs) ≡ x86_Program_P(inputs)


```

即对于所有可能的输入状态，EVM程序和x86程序产生相同的输出状态（包括栈、内存、存储、Gas等）。

## 2.3 关键技术

1.  **基于Isabelle的形式化验证：**使用Isabelle进行语义建模与证明
    
2.  **符号执行与形式化验证**：使用Z3求解器进行符号执行和等价性证明
    
3.  **程序级语义建模**：将整个程序直接建模为逻辑公式，而非逐步执行
    
4.  **状态空间抽象**：对EVM状态（栈、内存、存储、Gas）和x86状态（寄存器、内存、标志位）进行统一建模
    
5.  **等价性证明**：使用反证法，通过证明不存在反例来证明等价性

# 3 设计方案

本方案实现了EVM AOT编译器的形式化验证系统，通过程序级语义等价性验证，证明编译后的x86代码与原始EVM字节码在所有输入下产生相同的执行结果，从而保证编译器的正确性。

## 3.1 整体框架

### 3.1.1 整体架构图

本系统采用分层验证架构，将EVM AOT编译器的验证分为前端验证和后端验证两个层次，每个层次采用不同的验证策略：

![image](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/a/Y1ljYQwXUW18LEJx/d4135d7b7b67465dbca2622654df7af10625.png)

**架构说明：**

1.  **编译流程**：
    
    *   **前端编译**：将EVM Bytecode编译为EVM IR
        
    *   **后端编译**：将EVM IR编译为x86-64（或arm64等）机器码
        
2.  **验证流程**（虚线）：
    
    *   **前端验证**（Isabelle白盒）：
        
        *   验证EVM Bytecode到EVM IR的转换正确性
            
        *   使用Isabelle进行语义建模和证明
            
    *   **后端控制流验证**（Isabelle白盒）：
        
        *   验证TAG、JUMP、JUMPI等控制流指令的语义等价性
            
        *   使用Isabelle进行控制流语义证明
            
    *   **后端Block验证**（Z3黑盒）：
        
        *   以Block为粒度验证EVM IR Block与x86 Block的语义等价性
            
        *   使用Z3求解器进行符号执行和等价性检查
            

### 3.1.2 验证分层设计

验证系统采用三层验证架构：

1.  **前端验证层（Isabelle白盒）**
    
    *   **验证对象**：EVM Bytecode → EVM IR的转换
        
    *   **验证方法**：Isabelle形式化证明
        
    *   **验证内容**：指令级语义建模、转换规则证明、语义保持性证明
        
    *   **特点**：完全白盒，深入编译器前端实现细节
        
2.  **后端控制流验证层（Isabelle白盒）**
    
    *   **验证对象**：EVM IR控制流指令（TAG、JUMP、JUMPI）→ x86-64控制流指令
        
    *   **验证方法**：Isabelle形式化证明
        
    *   **验证内容**：控制流语义定义、转换规则证明、路径等价性证明
        
    *   **特点**：白盒验证，关注控制流转换的正确性
        
3.  **后端Block验证层（Z3黑盒）**
    
    *   **验证对象**：EVM IR Block → x86-64 Block的语义等价性
        
    *   **验证方法**：Z3 SMT求解器
        
    *   **验证内容**：Block级别符号执行、输入输出关系建模、等价性检查
        
    *   **特点**：黑盒验证，以Block为粒度，不依赖CFG，独立验证每个Block
        

### 3.1.3 验证策略说明

**白盒验证 vs 黑盒验证：**

*   **白盒验证（Isabelle）**：
    
    *   需要深入理解编译器实现细节
        
    *   可以证明转换规则的正确性
        
    *   适用于控制流等关键部分的验证
        
    *   需要大量形式化证明工作
        
*   **黑盒验证（Z3）**：
    
    *   将编译器视为黑盒，只关注输入输出
        
    *   通过符号执行验证语义等价性
        
    *   适用于Block级别的语义验证
        
    *   验证效率高，易于扩展，对于后续实现的变动不敏感
        

**分层验证的优势：**

1.  **关注点分离**：前端、控制流、Block语义分别验证，降低复杂度
    
2.  **验证效率**：关键部分用Isabelle严格证明，常规部分用Z3高效验证
    
3.  **可扩展性**：Block验证可以独立扩展，支持更多指令类型
    
4.  **可维护性**：各层验证相对独立，便于维护和更新
    

## 3.2 编译器前端形式化验证（Isabelle白盒）

编译器前端负责将EVM Bytecode转换为EVM IR。前端验证采用Isabelle进行完全白盒验证，深入编译器实现细节，证明转换的正确性。

### 3.2.1 验证目标

前端验证的主要目标是：

1.  **语义保持性证明**：证明EVM Bytecode到EVM IR的转换保持语义不变
    
2.  **转换规则正确性**：证明前端编译器的转换规则是正确的
    
3.  **完整性验证**：验证所有EVM Bytecode指令都能正确转换为EVM IR
    

**形式化目标：**

对于任意EVM Bytecode程序 `P_bytecode` 和其对应的EVM IR程序 `P_ir`，证明：

```haskell
∀ inputs. semantics_bytecode(P_bytecode, inputs) = semantics_ir(P_ir, inputs)

```

即对于所有可能的输入状态，EVM Bytecode和EVM IR产生相同的执行结果。

## 3.3 编译器后端形式化验证

编译器后端负责将EVM IR转换为x86-64机器码。后端验证采用混合策略：控制流部分使用Isabelle白盒验证，Block语义部分使用Z3黑盒验证。

### 3.3.1 后端控制流验证（Isabelle白盒）

后端控制流验证专注于验证TAG、JUMP、JUMPI等控制流指令的转换正确性。

#### 3.3.1.1 验证目标

1.  **控制流语义等价性**：证明EVM IR控制流指令与x86-64控制流指令的语义等价
    
2.  **跳转目标正确性**：证明JUMP/JUMPI的跳转目标在x86代码中正确实现
    
3.  **路径条件等价性**：证明条件跳转（JUMPI）的条件判断在x86代码中正确实现
    

**形式化目标：**

对于EVM IR控制流指令序列和对应的x86-64控制流指令序列，证明：

```haskell
∀ state. control_flow_semantics_ir(ir_control_flow, state) = 
         control_flow_semantics_x86(x86_control_flow, state)

```

### 3.3.2 后端Block验证（Z3黑盒）

后端Block验证以Block为粒度，使用Z3求解器进行黑盒验证，不依赖CFG，独立验证每个Block的语义等价性。

#### 3.3.2.1 验证目标

1.  **Block语义等价性**：证明EVM IR Block与对应x86 Block的语义等价
    
2.  **输入输出关系一致性**：证明对于相同的输入，两个Block产生相同的输出
    
3.  **独立性验证**：每个Block独立验证，不依赖其他Block或CFG信息
    

**形式化目标：**

对于EVM IR Block `ir_block` 和对应的x86 Block `x86_block`，证明：

```haskell
∀ inputs. block_semantics_ir(ir_block, inputs) = block_semantics_x86(x86_block, inputs)

```

## 4.6 风险与缓冲

**主要风险**：

1.  Isabelle形式化证明复杂度可能超出预期
    
2.  Z3求解性能可能成为瓶颈
    
3.  x86指令语义建模复杂度可能超出预期
    
4.  状态映射的复杂性可能导致验证困难
    
5.  证明自动化程度可能低于预期
    
6.  各步骤证明的复杂度可能不同，需要根据实际情况调整
    
7.  后端Block验证的指令支持扩展可能需要大量工作
    
    

**建议缓冲**：

*   在详细设计和开发阶段根据实际情况预留适当缓冲时间
    
*   后端开发阶段工作量较大（4-8个月），建议预留20-30%的缓冲时间
    
*   前端和后端可以并行开发，但需要协调接口和依赖关系
