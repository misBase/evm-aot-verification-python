# 1 概述

编译器后端负责将EVM IR转换为x86-64机器码。后端验证采用混合策略：控制流部分使用Isabelle白盒验证，Block语义部分使用Z3黑盒验证。

## 1.1 验证策略

后端验证分为两个层次：

1.  **后端控制流验证（Isabelle白盒）**：
    
    *   验证TAG、JUMP、JUMPI等控制流指令的语义等价性
        
    *   使用Isabelle进行控制流语义证明
        
2.  **后端Block验证（Z3黑盒）**：
    
    *   以Block为粒度验证EVM IR Block与x86 Block的语义等价性
        
    *   使用Z3求解器进行符号执行和等价性检查
        
    *   不依赖CFG，独立验证每个Block
        

# 2 后端控制流验证（Isabelle白盒）

后端控制流验证专注于验证TAG、JUMP、JUMPI等控制流指令的转换正确性。

## 2.1 验证目标

1.  **控制流语义等价性**：证明EVM IR控制流指令与x86-64控制流指令的语义等价
    
2.  **跳转目标正确性**：证明JUMP/JUMPI的跳转目标在x86代码中正确实现
    
3.  **路径条件等价性**：证明条件跳转（JUMPI）的条件判断在x86代码中正确实现
    

**形式化目标：**

对于EVM IR控制流指令序列和对应的x86-64控制流指令序列，证明：

```haskell
∀ state. control_flow_semantics_ir(ir_control_flow, state) = 
         control_flow_semantics_x86(x86_control_flow, state)


```

## 2.2 验证方法概述

验证方法包括：

1.  **TAG指令验证**：证明TAG指令转换为x86标签的正确性，包括栈深度检查的实现
    
2.  **JUMP指令验证**：证明JUMP指令转换为x86 JMP指令的正确性，包括跳转目标地址计算
    
3.  **JUMPI指令验证**：证明JUMPI指令转换为x86条件跳转的正确性，包括条件判断的实现
    
4.  **控制流路径等价性证明**：将所有其他指令标记为已验证，证明任意输入下编译器后端的输入与输出结果等价
    

**具体验证设计将在详细设计文档中给出。**

# 3 后端Block验证（Z3黑盒）

后端Block验证以Block为粒度，使用Z3求解器进行黑盒验证，不依赖CFG，独立验证每个Block的语义等价性。

## 3.1 验证目标

1.  **Block语义等价性**：证明EVM IR Block与对应x86 Block的语义等价
    
2.  **输入输出关系一致性**：证明对于相同的输入，两个Block产生相同的输出
    
3.  **独立性验证**：每个Block独立验证，不依赖其他Block或CFG信息
    

**形式化目标：**

对于EVM IR Block `ir_block` 和对应的x86 Block `x86_block`，证明：

```haskell
∀ inputs. block_semantics_ir(ir_block, inputs) = block_semantics_x86(x86_block, inputs)


```

## 3.2 Block语义建模概述

Block语义建模包括：

1.  **EVM IR Block语义建模**：使用Z3对EVM IR Block进行语义建模，包括处理TAG操作的栈深度检查（3条路径合并）
    
2.  **x86 Block语义建模**：使用Z3对x86 Block进行语义建模，包括处理所有x86指令类型
    
3.  **状态映射**：实现EVM状态到x86状态的映射，以及x86状态到EVM状态的映射
    

**具体建模设计将在详细设计文档中给出。**

## 3.3 验证方法概述

验证方法包括：

1.  **Block级别的符号执行**：
    
    *   输入符号化：将Block的输入表示为Z3符号变量
        
    *   状态转换建模：将Block内的每个操作/指令建模为状态转换函数
        
    *   输出提取：从最终状态中提取输出Z3公式
        
2.  **输入输出关系建模**：
    
    *   建立EVM IR Block的输入输出关系
        
    *   建立x86 Block的输入输出关系
        
    *   实现状态映射（EVM状态↔x86状态）
        
3.  **等价性检查**：
    
    *   使用Z3求解器检查两个Block的语义等价性
        
    *   如果Z3返回UNSAT，说明不存在反例，Block等价
        
    *   如果Z3返回SAT，说明存在反例，需要分析并修复问题
        

**具体验证方法设计将在详细设计文档中给出。**

## 3.4 Block验证的特点

1.  **独立性**：每个Block独立验证，不依赖CFG，可以并行验证多个Block
    
2.  **黑盒性**：不关心编译器如何生成x86代码，只验证输入输出关系的等价性，适用于各种优化策略
    
3.  **可扩展性**：新增指令类型只需扩展语义建模，不需要修改验证框架

## 5.6 风险与缓冲

**主要风险**：

1.  Isabelle形式化证明复杂度可能超出预期
    
2.  Z3求解性能可能成为瓶颈
    
3.  x86指令语义建模复杂度可能超出预期
    
4.  状态映射的复杂性可能导致验证困难
    

**建议缓冲**：在详细设计和开发阶段根据实际情况预留适当缓冲时间
