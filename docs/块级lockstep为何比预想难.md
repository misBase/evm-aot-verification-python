# 块级 lock-step 等价：为什么比预想难

> 2026-09-28。数据来自 CErc20 / Safe 的全量运行（R16–R25）和单块探测。

## 0. 预想与结论

预想是这样的：
1. 每个块的指令不多；
2. 每个块需要的栈深度可以算出来；
3. 两边的翻译公式一样，所以应该很容易证出来；
4. 内存只需要在用到的地方符号化。

这四条在**单条指令**的层面基本都对，单指令等价测试也确实早就全部通过了。块级之所以难，是因为到了块这一级，每一条假设都会被放大或者被打破：

| 预想 | 实际情况 | 见 |
|---|---|---|
| 块的指令少 | EVM 指令少；但每条 EVM 指令对应的 x86 代码里**内联了大量检查分支** | §1 |
| 翻译公式一样 | **值一样，形状不一样**。求解器只认形状，形状不同就要靠 bit-blast 硬证 | §2 |
| 栈深度可算 | 栈深度确实能算；但块入口的状态**不只有栈**，参数一多，实例就多 | §3 |
| 内存用符号即可 | 符号化**本身就是难点**：别名、符号长度、非线性 gas 都从这里来 | §4 |

总体来看：方案本身可行，难的地方在于"让两边的公式长得一样"，这部分工作量远大于预期。

## 根本原因：从"算出来相等"变成"证明恒等"

- **整体验证**：从一个具体的初始状态出发（msize = 0，fmp = 0x80，gas 是具体值），内存地址、大小和 gas 都是常数。两边各自**算出**一个值，比较一下就行。写法不同、检查分支、平方运算，都被常量求值直接消化掉了。
- **块级验证**：每个块都要对**所有**合法的入口状态成立，所以栈、msize、fmp、gas 都是符号值。这时"两边相等"不能再靠算出来，而是要**证明两套独立的实现对任意输入都恒等**：一套是编译器生成的 x86 代码，另一套是 EVM 语义模型。

后文的难点都是这一转变的直接后果：

| 转变的后果 | 表现 |
|---|---|
| 两套实现的写法和算法不同，常数不再能掩盖 | 只能靠求解器证明代数恒等，遇到乘除法和内存数组就证不动（§2） |
| x86 按值分支（快路径、各种检查），模型不分支 | 路径数单方面膨胀（§1） |
| 内存指针、长度、gas 都是符号值 | 别名、循环归纳、`w²` 非线性（§4） |

整体验证能证出 muti_block 这类用例，是因为它们规模小、没有 MUL、状态是具体的；用在 CErc20/Safe 上，它根本跑不完。块级方案付出"证明恒等"的代价，换来的是能逐块分解、并且覆盖所有入口状态的结论。

## 1. 块的指令少，但 x86 代码多，分支更多

**例子：Safe 6898**（`revert("GSxxx")` 的错误编码块）

```
EVM：28 个操作
  fmp = MLOAD(0x40); MSTORE(fmp, selector); MSTORE(fmp+4, 32);
  MSTORE(fmp+36, 5); MSTORE(fmp+68, "GSxxx"); REVERT(fmp, 100)
x86：830 条指令，75 个条件跳转，28 个退出点
```

原因是编译器在**每一次内存访问**前都内联了一整套检查。下面是 `MLOAD(0x40)` 这一条指令展开后的 x86 代码：

```
offset 高 limb 非零?           → 错误退出
offset+32 溢出?                → 错误退出
新大小 > 0x1FFFFFFFE0?         → OOG 退出
新大小 ≤ 当前 msize?           → 快路径（不扩容，费用 0）
否则：费用 = 3w + w²/512 − 上次费用   ← 含非线性乘法
剩余 gas < 费用?               → OOG 退出
```

EVM 语义模型把扩容费写成**一个不分叉的公式**，x86 则是**真的在分叉**。所以两边的路径数不一样：

| Safe 6898（同一个调用点） | EVM 路径 | x86 路径 | x86 执行耗时 |
|---|---|---|---|
| 内存大小、fmp 为具体值 | 6 | 6 | 0.4s |
| 内存大小、fmp 为符号值 | 27 | **429** | 398s |

证明要对 x86 的每一条路径逐一说明它对应哪一条 EVM 路径，所以工作量跟着路径数一起膨胀。

## 2. 翻译公式"一样"，其实只是值一样，形状不一样

Z3 能瞬间看出 `f(a) = f(a)`，但遇到 `f(a) = g(a)`，即便它们处处相等，也要把两边展开到位级再比较。这一步 bit-blast 遇到乘法、除法或者长串内存写入时，往往要跑几十分钟，最后还可能是 unknown。实际碰到的"同值异形"有下面几类，每一类都曾让某个块卡住：

| # | 两边的写法 | 来源 | 代价 → 修复后 |
|---|---|---|---|
| a | MUL：EVM 是 `a·b`，x86 是 `b·a`，limb 的累加顺序也不同 | 编译器的操作数顺序 | 14263 卡住 → 模型按 codegen 形状对齐（你已批准） |
| b | 内存地址：EVM 用 `偏移`，x86 用 `R15 + 偏移` 访问字节数组 | x86 按真实地址访存 | 4236 超过 2300s → **89s** |
| c | 字节拼接：`Concat(Extract(63,8,X), 4+X[7:0])` 对比 `X+4` | 单字节写回、simplify 把低字节下推 | 4236、588 卡住 |
| d | 取整：x86 是 `32·Concat(0⁵,W)`，EVM 是 `Concat(W,0⁵)` | x86 先除后乘，EVM 用移位 | 12930 从 2092s unknown → **261s** |
| e | DIV：x86 分快路径和 builtin 两段实现，EVM 是 holiman 算法 | 两种算法 | 14263 卡住 → DIV summary |
| f | 相等性：x86 用借位链判断，EVM 直接用 `==` | 比较的实现方式 | 路径条件无法直接对上 |

**以 (d) 为例**：两边都要算 `words²`（内存扩容费）。x86 的 `words` 由 `32·Concat(0⁵,W)` 得来，EVM 的由 `Concat(W,0⁵)` 得来，数值相等。可一旦放进平方项，Z3 就得展开 64×64 位乘法器去证明两个平方相等，于是解不动。加一条经过证明的重写 `2ᵏ·Concat(0ᵏ,X) → Concat(X,0ᵏ)`，两边就逐字相同了，平方项被当作同一个未解释函数，一秒内即可证完。

**这一节的教训**："翻译公式一样"必须具体到**语法上一样**，不能只是数学上一样。块级证明的主要工作量，就是把这些同值异形的写法逐个找出来，再逐个对齐。

## 3. 栈深度可算，但入口状态不只有栈

块入口要约束的状态有：栈深度 k、栈上的常量、内存大小 msize、空闲内存指针 fmp，以及 gas、callEngine 字段等。我们按 `(k, msize, fmp, 栈常量)` 给每个块做**专门化**。参数取值一多，实例就多：

- **Safe 6898**：一共 42 个实例。Safe 里每个 `require(…, "GSxxx")` 都跳到这个块，而错误字符串会作为栈常量进入专门化，于是"调用点 × 错误码 × 栈深"的每种组合都是一个实例。
- **CErc20 4236**（`accrueInterest` 调用利率模型的那一段）：13 个实例。各调用方的返回地址不同，就是不同的实例。

同一个上下文里，如果 `(msize, fmp)` 的取值超过 8 种，就会**放宽成符号值（TOP）**，以保证实例数有限。可是一旦变成 TOP，就会触发 §1 那样的路径爆炸（慢约 1000 倍）。实例太多会拖慢整体进度，放宽成符号值又会让单个实例难证，两头都有代价。

---

## 4. 内存用符号即可？符号化本身就是难点

### 4.1 两个符号指针的别名
**例子：CErc20 12930**（ABI 编码动态 `bytes`）

```
mstore(pos, 32)
len = mload(value)          // pos 和 value 都是符号值
mcopy(pos+64, value+32, len)
```

`pos` 和 `value` 所指的两段内存可能重叠，一共有 63 种错位方式（pos = value+k，k = −31…31）。EVM 侧把这些情况展开成一个 104KB 的逐字节 ite，x86 侧则是 32 个 Store 叠在一起再读取。Z3 需要把每一种重叠情况都对上，因此解不动。

解决办法是**按重叠差值分情况**：每种情况下别名都变成了常量，1 秒内就能证完；剩下"完全不重叠"这一种，先证一条不重叠引理再处理。

### 4.2 符号长度 → 循环
`MCOPY`、`CALLDATACOPY`、`RETURNDATACOPY` 的长度是符号值，对应的 x86 拷贝循环不能展开，只能靠**归纳证明**来概括它的效果。

### 4.3 非线性 gas
内存扩容费里有 `words²/512`。符号长度或符号 fmp 会让 `words` 成为符号值，于是路径条件和 gas 义务里都出现了非线性乘法：
- 可达性查询从毫秒级涨到秒级。旧的 250ms 超时下，约一半查询得到 unknown，只能按"可达"处理，不可行的路径因此没被剪掉，又继续分叉。
- gas 相等的义务要 bit-blast 平方运算。

**Safe 588**（`fallback()` 的转发代码）就是这种情况：`calldatacopy`、`call`、`returndatacopy` 的长度全是符号值，要做三次扩容计费。这个块在完整预算下需要 1206s 才能证完。

## 5. 证明义务的数量是"路径对"的数量

每个块要证明：x86 的每条路径都对应到 EVM 的某条路径，且终止时的状态相等。

- CErc20 4236：EVM 24 条 × x86 35 条路径 → 1796 次检查。STATICCALL 的参数里带着整个 memory，要把两边的参数逐个证成相等才能合并，光这一步就花了 700s。
- CErc20 12930：EVM 28 条 × x86 46 条路径；某些义务单条就要跑几十分钟。

---

## 6. 工程层面的放大

- **发现依赖前驱**：一个块的专门化参数，是从它前驱的出口状态里推出来的。早期实现里，块证不过就不去发现它的后继，所以一个难块会挡住整棵子树（R16 里有 303 个块从未被访问）。已改为发现与证明解耦。
- **串行调度**：一次只证一个节点，一个 3600s 的难块会让整条队列停下来。已改为首轮给短预算、难块延后重试。
- **对负载敏感**：路线内部的超时是按墙钟算的，机器越忙，能证出的义务越少。

## 7. 应对方法与效果

| 手段 | 性质 | 典型效果 |
|---|---|---|
| 规范化重写（内存视图、字节拼接、取整…），每条重写都要单独证明 | 等价变换 | 4236：2300s → 89s；12930：2092s → 261s |
| DIV / MUL / memgas / CALLDATALOAD / MCOPY summary：每种代码形状证一次引理，命中时直接替换 | 组合证明，fail-closed | 6898 TOP：x86 路径 429 → 14，1800s 未证完 → 401s |
| 别名分情况、终止目标拆分、数组外延性 | 等价的分情况证明 | 12930 的三条义务、9733 的 `pair_22_7`（91s）证出 |
| 可达性加速：模型见证复用、乘法抽象 | 只剪 UNSAT 的分支 | x86 执行快 3–4.5 倍 |
| 调度改进、proof cache | 工程 | 一轮覆盖的块数明显增加 |

所有手段都遵守同一条原则：**只相信 UNSAT；每一步重写或替换都有证明记录；证不出就退回原始执行，绝不当作已证**。

---

## 8. 结论

- 预想中的"指令少、栈深可算、公式一样"，到了块级分别变成了：分支多、实例多、**同值异形**。其中同值异形是主要成本。
- 这些问题不是方案本身的缺陷，而是"两个独立写出的语义模型"必然存在的形状差异。它们可以一类一类地被规范化或组合证明消掉，每消掉一类，相关的块往往就从几十分钟降到一两分钟。
- 截至 09-28 14:00：
  - 已知难块 4236、6898、14263、588 在完整预算下能证出；12930 卡住的三条义务都已证出（整个节点待复测）。
  - **Safe 9733 仍未证完**：原先最难的 `pair_22_7` 已在 91s 内证出，但又暴露出一条 `x86_maps_23_29`（260s 后 unknown），而且整个节点有 1565 条义务，耗时 3186s，贴近 3600s 的预算。
  - 全量运行 R25 正在进行。剩下的主要成本是 ABI 解码类块的 CALLDATALOAD 引理（每种代码形状约 330s），以及整轮运行的墙钟时间。
